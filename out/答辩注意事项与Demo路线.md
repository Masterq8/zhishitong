## 三、答辩关键论点

### 必须强调的核心观点
1. **不是 ChatGPT 套壳**：AI 嵌入完整审批流程（填表→检索→合规→决策→归档），不是孤立对话
2. **人保留最终决策权**：AI 提供证据和建议，不是行政结论
3. **三层降级保证可用性**：云端 LLM → 本地 Qwen3-14B → 规则兜底
4. **完整工程闭环**：17,000 行代码 + 99 API + 16 张表 + 监控 + 安全
5. **真实可运行**：所有截图来自真实系统，非设计稿

### 避免的表达
- ❌ 「完全自动化审批」
- ❌ 「吊打传统系统」
- ❌ 「最强 AI 审批系统」
- ❌ 「一键解决所有问题」

### 推荐的表达
- ✅ 「AI 辅助流程，人保留最终决策」
- ✅ 「系统将 AI 嵌入审批流程中的特定环节」
- ✅ 「通过分层架构平衡效果与安全」
- ✅ 「该设计避免了黑箱 AI 自动审批的合规风险」

## 四、常见陷阱与应对

| 陷阱 | 应对 |
|------|------|
| 评委质疑「为什么不直接用 ChatGPT」 | 展示 RAG 政策检索、本地模型隐私保护、审批流程闭环——这不是对话工具 |
| 评委质疑「本地模型效果如何」 | 承认本地模型精度不如云端，但强调其隐私、离线、成本优势，以及 LoRA 微调的持续优化路径 |
| 评委质疑「数据从哪来」 | 政策知识库来自公开校园制度文件，审批模板来自高校实际流程调研 |
| 评委质疑「实际落地有多远」 | 系统已完整可运行，差距在生产环境部署和用户测试，不是功能缺陷 |
| 时间不够 | 优先保证：背景→架构→HITL→AI分层→Demo→创新点，可跳过前端设计和工程化 |
